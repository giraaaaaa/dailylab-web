# 실험 네 개 개편 결과

> 접히는 도시의 팝업 모형은 이후 폐기했다. 현재 구현은 [도시 재구성 결과](city-rebuild-result.md)를 따른다. 아래 내용은 첫 개편 당시의 기록이다.

2026-10-21. 기존 `feat/lab-specimens` 작업 트리에 구현. 운영 배포는 하지 않음.

## 바꾼 경험

- **자석 타일:** 처음에는 붙어 버티고, 충분히 당기면 분리된다. 가까이 놓으면 정렬하며 붙고, 멀리 놓으면 받침 옆으로 내려놓는다. 타일 아래 자석과 빈 자리가 드러난다. 흑연색 받침과 세라믹 타일로 재질 대비를 높였다.
- **탄성 막:** 누르는 순간 튀어나오던 높이를 없애고 카메라를 향한 조작 평면에 잡은 점을 맞췄다. 표면의 인쇄 격자와 늘어난 곳의 코발트 반사가 변형 방향을 보여준다. 큰 기울기에서 복원력을 높이고, 놓는 속도를 첫 진동에 더한다.
- **불가능한 방:** 공 하나가 문 경계에서 양쪽 방에 잘려 보인 뒤, 위치·속도·회전을 유지한 채 넘어간다. 도착 방은 중력이 옆 벽을 향한다. 공 굴리기·문 회전·다른 쪽에서 보기로 다시 실험할 수 있다. 받침, 프레임, 줄눈과 착지면으로 장면을 다시 구성했다.
- **접히는 도시:** 고정 바닥의 64채를 여섯 팝업 모형으로 교체했다. 책등을 중심으로 바닥판과 도로가 접히며, 벽은 길이를 유지하고 지붕 두 조각이 안으로 접힌다. 정면이 열린 종이 건축 모형이다.

네 방에 기존 접촉·클릭·종이 마찰 효과음을 연결했다. 공통 소리 켜기/끄기 설정을 사용하며 기본은 무음이다. 새 오디오나 라이브러리를 추가로 생성·설치하지 않았다.

## 확인

- `npm test`: 17개 통과. 포털 왕복 좌표·속도, 실제 공의 통과와 옆 벽 착지, 팝업 지붕 길이와 벽 접점, 막의 안정성·고정 경계·속도 전달을 포함한다.
- 브라우저: 타일을 분리해 멀리 놓았다가 다시 붙이기, 막 드래그와 복원, 공 발사·통과·착지·반대편 관찰, 도시 중간 접힘과 자동 왕복을 확인했다.
- 1280px 데스크톱과 390×844 세로 화면을 확인했다. 세로 화면에는 별도 시점·프레이밍을 적용했다.
- 네 방의 실제 화면을 다시 기록해 목록 영상·포스터를 교체했다. 프레임별 시각 확인도 했다.
- 화면 기록은 `docs/rework-preview/`에 있다.

## 남는 한계

- 타일은 범용 자석·강체 엔진이 아니다. 분리·재결합을 위한 상태와 스프링, 간단한 겹침 방지 규칙을 쓴다. 다수의 자유 타일을 쌓는 체험은 범위 밖이다.
- 막은 비선형 장력 보정을 넣은 격자 모델이며 실제 고무의 재료 모델이 아니다. 변형 위치를 보여주는 색은 높이에 반응한다.
- 포털의 ‘다른 쪽에서 보기’는 관찰 시점의 전환이며 플레이어가 연속해서 걸어 통과하는 자유 이동은 아니다. 공은 연속해서 통과한다. 포털 프레임 바깥 충돌까지 푸는 범용 물리 공간은 아니다.
- 도시는 앞뒤를 닫은 건물이 아니라, 패널의 접힘을 관찰하는 단면 모형이다. 종이 탄성이나 모든 패널의 충돌을 계산하지 않는다.
- 실제 휴대폰의 터치 지연·발열·FPS와 효과음의 청감 품질은 이번 검증에서 측정·청취하지 않았다. 60fps나 기존 작품보다 우수하다는 결과를 주장하지 않는다.

기존 기획서는 당시의 분석·목표 기록으로 유지한다. 이번 구현에서 완성한 범위와 단순화한 부분은 이 문서를 따른다.
